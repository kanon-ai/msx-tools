# MSX Image Converter v1.0

通常のPNG・JPEG・WebPなどを、初代MSXのPCG、または本プロジェクトのV9968用16色画像へ変換するローカルツールです。

`START.cmd` を実行し、表示されたブラウザーで画像を選択してください。画像は127.0.0.1のPythonサーバーだけに送られ、外部サービスには送信されません。画像生成AIを呼び出す機能はありません。

## 対応形式

### TMS9918A / SCREEN 2

- 固定パレットの色1〜15から選択。色0は透明扱いのため除外。
- 横8ドットの各行につき2色以内。各色対を全探索して選びます。
- 輪郭付近の画素を重くする調整、使用色の制限、縮小方式、軽いシャープ処理。
- 幅・高さは8の倍数。PCG枚数も表示します。
- PNG、`patterns.bin`、`colors.bin`、検証JSONを出力。
- 256×192の場合はさらに `names.bin`、16KBの `vram.bin`、BLOAD形式の `image.sc2`、16KBの静止画確認用 `preview-msx1.rom` を出力。

フルSCREEN 2の出力は、パターン0000–17FF、名前1800–1AFF、カラー2000–37FF、スプライト属性先頭1B00に終端208を配置します。標準のSCREEN 2設定を想定し、実行時にPCGを共用・マスクしているゲームへ無条件に貼れる形式ではありません。

任意サイズのPCGは左から右、上から下のタイル順、その中で8行の順です。カラーの上位4bitが前景色、下位4bitが背景色、パターンの最上位bitが左端です。配置やタイル共有、背景との合成はゲーム側で設計します。

プレビューのRGBはTMS9918A固定色の代表値です。実機の映像出力、エミュレーターの色設定によって見える色は変わります。

### V9968 / 本プロジェクトの4bpp形式

- 16色、RGB各5bitのパレット。
- 画像からパレットを自動生成、または既存のRGB555パレットを固定。
- 自動パレットでは最暗部・明部を残し、RGB555化で重複した色枠を再配置します。
- `pixels-4bpp.bin` は行優先、左側の画素が上位ニブル。
- `palette-rgb5.bin` はR、G、Bの各5bit値を別々のバイトに格納した48バイト。
- `palette.json` にRGB5/RGB8配列、PNG、検証JSONを出力。

これは既存のPRISM DESCENTの画素・パレット形式に合わせたプリセットです。V9968の全描画モードや任意のハードウェア版を対象にした万能形式ではありません。VRAMアドレス、画面モード、レイヤーの設定はROM側で行います。

固定パレットJSONの例：`{"rgb5": [[0,0,0], ...16組...]}`。画面では `target_palette_rgb5` キーや配列だけのJSONも読み込めます。

## 使い方

1. `START.cmd` を起動。
2. 画像を選択するかドロップ。
3. 出力形式、寸法、配置方法、縮小方式を選ぶ。
4. TMSなら使用色を選ぶ。「金属・光」は8色のプリセット。
5. 変換し、等倍や拡大、誤差マップで確認。
6. PNG、またはバイナリを含むZIPを保存。

「縦横比を保つ」は黒い余白を追加。「中央を切り抜く」は端を切り落とします。「指定寸法へ伸縮」は形が変わるため意図して選択してください。ディザは使いません。

輪郭優先度は色対の選択の重み付け、輪郭強調は縮小後の原画に対するシャープ処理です。どちらも失われたディテールを新しく描くものではありません。

PCG枚数や2色制約は検査できますが、ゲーム内の転送時間、スプライト制限、タイルの空き、スクロールの継ぎ目、敵弾の見やすさまでは自動保証しません。生成画像を小さい枠に縮めるだけで美術が完成するわけではなく、原画の画素設計と配色の調整に使う道具です。

## インストール・CLI

Python 3.10以上、Pillow、NumPyが必要です。

```powershell
python -m pip install -r requirements.txt
python app.py

python convert.py input.png --mode tms9918a --width 256 --height 192 --out out/tms
python convert.py input.png --mode tms9918a --width 80 --height 128 --colors 1,4,5,6,7,11,14,15 --out out/pcg
python convert.py input.png --mode v9968 --width 256 --height 768 --edge 2 --out out/v9968
python convert.py input.png --mode v9968 --width 256 --height 212 --palette palette.json --out out/fixed
```

アプリのポートは `python app.py --port 8792` で変更できます。元画像のEXIF回転を反映し、アルファは黒へ合成します。出力は最大1048576画素。元画像はブラウザーからは23MB／3200万画素までです。

## 検証と実際の利用例

`python -m unittest discover -s tests -v` で9件の検証を実行できます。

- 8ドット2色制約、全色対探索の最小誤差、PCGの往復一致。
- SCREEN 2のVRAM配置、SC2ヘッダー、確認用ROM形式。
- V9968のRGB555値、4bppのニブル順、固定パレット順序。
- 単色入力、再現性、透明画像、不正寸法、ZIP内の検証情報。

このリポジトリにはツール本体・Web画面・テストを保存します。入力画像、ゲーム素材、生成出力、BIOS、個人のエミュレーター作業フォルダーは含めません。

開発時には、出力した静止画ROMをopenMSX Sony HB-101で起動し、パターン・カラー・名前テーブルの転送一致と厳密VRAMタイミング違反0件を確認しています。別プロジェクトの昼の都市MAPではV9968向け4bpp出力をROMへ組み込み、対応openMSXでの実行も確認しました。これらの素材と検証記録はゲーム側で管理しており、このリポジトリには同梱していません。

`verify_native.py` は任意の開発者向け検証です。実行する場合は、自分の画像をCLIで256×192のTMS形式へ変換し、出力先を `outputs/ai-tms-screen2` にしてください。openMSXとユーザー所有のSony HB-101 BIOSが別途必要です。通常の画像変換にエミュレーターは不要です。

実機での表示は未検証。既存ゲームのROMや素材は自動で書き換えません。出力したファイルを選んで取り込む方式です。BIOSは同梱しません。
